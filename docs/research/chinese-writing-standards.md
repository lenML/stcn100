# 中文技术写作标准与静态检查规则调研

调研日期：2026-10-04。

本文只做标准状态、适用范围、版权边界和工程化摘要。正文不复制标准全文，不使用标准表格、附录和条款原文作为规则数据。示例均为项目自拟测试语料。

## 1. 结论摘要

1. 通用中文正文应以 `GB/T 15834-2011`、`GB/T 15835-2011` 为标点和数字基线。
2. 涉及参考文献时，新文档默认采用 `GB/T 7714-2025`。`GB/T 7714-2015` 已废止。
3. 术语一致性不能只靠正则。需要首选术语表、禁用词表、缩写表、英文对应表和项目级配置。
4. 中文科技文档的静态检查应分为确定规则、候选规则、启发式规则。标点宽度等可自动修复；句义、术语正确性、引用完整性只应警告或保守修复。
5. 代码、URL、命令、路径、字段名、日志、配置值和转载原文必须进入豁免区，不能按中文正文标点规则处理。
6. 规则引擎应先解析文档结构，再做文本检测。仅按行扫描会产生大量误报。
7. 标准文本有版权边界。仓库只保存标准号、名称、官方链接、短摘要、自拟示例和规则实现，不保存标准 PDF、扫描件、OCR 文本或大段摘录。

## 3. 核心标准落地分析

### 3.1 标点符号

`GB/T 15834-2011` 是本项目的中文正文标点基线。静态检查应优先覆盖以下确定性问题：

| 问题 | 静态检查方向 | 默认处理 |
| --- | --- | --- |
| 中文正文混用英文标点 | `，。；：！？` 与 `,.;:!?` 的上下文判定 | 中文可修复；代码保护区内跳过 |
| 成对符号不匹配 | `“”`、`‘’`、`（）`、`〈〉`、`《》`、`【】` 配对 | 报警，可安全时修复 |
| 重复点号 | `，，`、`。。`、`！！`、`？？` | 报警或修复 |
| 省略号和破折号形态不稳定 | 中文正文中的 `……`、`——` 形态 | 按项目字体和格式配置修复 |
| 中文标点周围多余空格 | 标点前、左括号后、右括号前的空格 | 可修复 |
| 并列引号或书名号之间滥用顿号 | 并列项边界检测 | 警告，不默认自动删除 |
| 代码和正文边界不清 | 行内代码、围栏代码、URL、命令 | 强制进入保护解析 |

边界：该标准不替代 Markdown 规范，也不覆盖代码、命令、日志、配置和协议文本。对于转载原文、法律文本、用户生成内容和引用块，应默认只读检查或跳过。

### 3.2 数字用法

`GB/T 15835-2011` 面向出版物数字表达。工程规则不应把其中的编辑习惯机械套到版本号、哈希、端口、状态码和标识符上。

建议落地的检查族：

| 检查族 | 示例方向 | 风险 |
| --- | --- | --- |
| 阿拉伯数字与汉字数字混用 | 同一表格、同一段落、同一字段表达不一致 | 中 |
| 日期格式混用 | `2026年10月4日`、`2026-10-04`、`2026/10/04` 并存 | 低 |
| 时间格式混用 | 半角冒号、全角冒号、时分秒缺省不一致 | 中 |
| 数值分隔符混用 | 千分位、小数点、全角句点并用 | 高 |
| 范围表达混用 | 连字符、波浪号、汉字“至”并存 | 中 |
| 比例和百分数混用 | `50%`、`百分之五十` 混用 | 低 |
| 约数表达混用 | `约`、`大约`、`左右` 重复叠加 | 低 |

不能直接自动修复的场景：版本范围、数学区间、财务金额、实验数据、标准号和法规条文。此类内容应只警告，并要求人工确认。

### 3.3 参考文献

自 2026-07-01 起，`GB/T 7714-2025` 已实施。新文档应默认使用 2025 版。新文档中出现“按 `GB/T 7714-2015`”时应提示迁移。

静态检查可分为以下层次：

| 层级 | 可检查内容 | 是否可自动修复 |
| --- | --- | --- |
| 引用标记 | `[1]` 是否连续、是否重复、是否有对应条目 | 部分 |
| 条目结构 | 类型标识、作者、题名、来源、年份、页码、标识符是否存在 | 否 |
| 格式一致性 | 同类型条目字段顺序、标点、空格、大小写是否统一 | 部分 |
| 交叉一致性 | 正文引用、参考文献列表、脚注、图表来源是否闭环 | 否 |
| 标准版本 | 新文档是否仍引用已废止版本 | 可提示 |
| 资源类型 | 图书、期刊、会议、标准、报告、学位论文、专利、电子资源分别校验 | 否 |

参考文献规则应采用“格式解析器 + 项目配置”，不应只用一组正则替换。不同学科、期刊和机构可能有更严格模板。项目默认规则只负责国标兼容性和一致性，不声称覆盖所有出版模板。

### 3.4 术语一致性

`GB/T 10112-2019` 提供术语工作原则和方法上的参考。`GB/T 20001.1-2024` 更偏向标准起草中的术语部分，但对项目术语表设计有借鉴价值。

术语治理至少需要以下字段：

| 字段 | 含义 |
| --- | --- |
| 首选术语 | 文档默认使用形式 |
| 禁用术语 | 不推荐或已淘汰形式 |
| 允许同义术语 | 特定上下文可使用形式 |
| 缩写 | 大小写、扩展形式、首次出现要求 |
| 外文对应 | 英文、缩写、商标和产品名 |
| 定义 | 项目内可验证的短定义 |
| 反例 | 容易混淆但与首选术语不同的概念 |
| 适用范围 | 通用、编程、接口、学术、产品、运维等配置 |
| 来源 | 项目约定、行业标准、产品文档或团队术语库 |

可静态化的术语问题：

| 问题 | 检测方式 |
| --- | --- |
| 同一概念多词并存 | 术语映射表 |
| 禁用词残留 | 禁用词表 |
| 缩写首次出现未展开 | 全文首次命中扫描 |
| 缩写大小写不一致 | 规范化表和大小写敏感匹配 |
| 中文名与英文名对应错误 | 术语映射表 |
| 同义词跨文件不一致 | 项目级索引 |
| 产品名、命令、字段名误翻译 | 产品名词典和保护区识别 |
| 定义循环或定义包含被定义词 | 术语表内部检查 |

不能静态确认的内容：定义是否科学、术语是否符合行业共识、两个近义概念是否真的同义。此类问题只能生成评审任务。

### 3.5 中英混排

`CY/T 154-2017` 适用于中文出版物中夹用英文的编辑场景。本项目可将其作为可选配置，而不是默认全局强制。

建议检查项：

| 检查项 | 默认策略 |
| --- | --- |
| 中英文之间空格 | 作为项目策略，不直接等同国标强制项 |
| 英文标点与中文标点边界 | 按所在语段和上下文判定 |
| 英文书名、报刊名、作品名标示 | 可按 `CY/T 154-2017` 配置 |
| 英文大小写 | 依赖产品名、缩写和专有名词表 |
| 英文转行和断词 | 静态 lint 只保留检查接口，不默认执行 |
| 上下标、变量、单位 | 交给文档格式配置和单位规则 |
| 代码标识符 | 一律进入保护解析和术语白名单 |

W3C《中文排版需求》是工作组说明，不是国家标准。它适合指导换行、标点挤压、混排和渲染实现，不适合作为强制 lint 规范。

## 4. 中文科技文档常见问题

| 类别 | 常见问题 | 可能后果 | 静态检查可行性 |
| --- | --- | --- | --- |
| 标点 | 全角半角混用、成对符号不闭合、连续点号 | 可读性差，复制后出错 | 高 |
| 数字 | 同类数字格式不一致、日期格式混乱 | 数据误读 | 高 |
| 单位 | 数值与单位空格不一致、单位名称和符号混用 | 技术歧义 | 中 |
| 术语 | 同一概念多个名称，缩写未定义 | 认知负担和集成错误 | 高，依赖词典 |
| 专名 | 产品名、API 名、命令名大小写错误 | 命令失败或检索困难 | 高，依赖词典 |
| 中英混排 | 空格和标点风格漂移 | 排版不一致 | 中 |
| 句子 | 长句、多个转折、并列层级过深 | 难以理解 | 中，启发式 |
| 语法 | 主语缺失、指代不明、悬空修饰 | 责任主体或对象不清 | 低到中 |
| 冗余 | “进行...处理”“作出...优化”堆积 | 表达膨胀 | 中 |
| 模糊词 | “相关”“适当”“一定程度上”“可能”滥用 | 需求不可验证 | 中 |
| 结构 | 标题层级跳跃、同级标题粒度不一致 | 导航混乱 | 高 |
| 列表 | 列表引导句缺失、项目结构不平行 | 步骤遗漏 | 中 |
| 代码 | 路径、命令、变量未使用行内代码 | 误复制和误读 | 中 |
| Markdown | 围栏不闭合、表格断裂、锚点失效 | 渲染异常 | 高 |
| 交叉引用 | 图表、章节、公式编号断链 | 文档维护失败 | 高 |
| 引用 | 引用标记与文献表不匹配、旧标准残留 | 学术不完整 | 高 |
| 术语扩充 | 新术语未进入术语表 | 后续文档继续漂移 | 中 |
| 场景漂移 | 同一仓库不同文档采用不同规则 | 维护成本上升 | 高 |

### 5.2 默认级别定义

| 级别 | 含义 | 退出码建议 |
| --- | --- | --- |
| 错误 | 明确违反项目规则，或会破坏渲染、引用、命令执行 | 非零 |
| 警告 | 高概率问题，但受上下文影响 | 默认零，严格模式非零 |
| 信息 | 一致性或可维护性建议 | 零 |
| 关闭 | 当前配置不检查 | 不影响 |

### 5.3 自动修复边界

适合自动修复：

1. 中文正文中的标点宽度。
2. 重复点号。
3. `CN-TERM-001` 中无歧义的禁用术语替换。
4. 已知产品名、缩写、单位符号的规范化。
5. 中文标点周围多余空格。
6. Markdown 标题层级和结尾空格。

不适合自动修复：

1. 参考文献重排和补字段。
2. 数字体系改换。
3. 术语是否同义。
4. 长句拆分。
5. 指代消解。
6. 代码令牌是否应格式化为行内代码。
7. 用户引用、法规原文和转载内容。
8. 中英混排空格的绝对删除或插入。

## 6. 规则引擎建议

1. 解析层使用 Markdown AST，并保留原始字符偏移。
2. 保护层标记围栏代码、行内代码、HTML、自动链接、链接目标、YAML 前置元数据、数学公式和转义字符。
3. 文本层再执行标点、数字、术语、句式和引用扫描。
4. 索引层跨文件构建标题、术语、缩写、引用、链接和专名索引。
5. 诊断层统一输出规则 ID、级别、文件、范围、消息、来源、可修复性和修复建议。
6. 修复层必须按逆序替换字符范围，避免偏移漂移。
7. 配置层按通用、技术、编程、学术、出版配置启用规则。
8. 测试层每条规则至少有正例、反例、保护区内反例、边界例和修复结果例。
9. 术语词典和规则数据与执行代码分离，便于项目覆盖。
10. 规则元数据必须记录来源标准、项目自定义程度和当前版本日期。

## 7. 场景配置建议

| 配置 | 默认启用 | 说明 |
| --- | --- | --- |
| 通用中文 | 标点、数字、结构、Markdown | 默认配置 |
| 技术文档 | 通用规则、术语、缩写、符号、交叉引用、句式 | 适合设计文档和用户手册 |
| 编程文档 | 技术文档规则、代码令牌、路径、命令、API 名、链接 | 代码保护区和术语白名单更严格 |
| 学术文档 | 技术文档规则、参考文献、引文、表格题注 | 默认 `GB/T 7714-2025` |
| 出版编辑 | 通用规则、中英混排、排版、术语 | 可启用 `CY/T 154-2017` 相关配置 |
| 旧文档迁移 | 全规则、旧标准检测、风格漂移报告 | 默认只报告，不批量改正文 |

## 8. 静态检查无法覆盖的范围

以下问题不应由首版静态 lint 宣称可自动判定：

1. 技术事实是否正确。
2. 术语定义是否符合专业共识。
3. 论点、数据、推导和结论是否成立。
4. 引用内容是否支持正文观点。
5. 操作步骤是否真的可执行。
6. 译文是否忠实。
7. 文档是否满足目标读者的知识背景。
8. 图表是否准确表达数据。
9. 法律、合规、安全和行业监管要求。
10. 用户语气和品牌策略的最终选择。

这些内容应转为人工评审项、术语评审流程或独立校验器。

## 9. 版权与引用边界

| 边界 | 项目规则 |
| --- | --- |
| 标准正文 | 不复制、不打包、不镜像标准全文 |
| 标准表格和附录 | 不录入仓库作为规则数据 |
| 标准 PDF 和扫描件 | 不提交、不缓存、不再分发 |
| 采标国际标准 | 特别注意国际组织版权，按官方公开范围处理 |
| 条款引用 | 只引用标准号、名称、条款号、必要短摘要和官方链接 |
| 示例 | 使用项目自拟、合成、非标准原文示例 |
| 规则映射 | 记录“规则来源”和“项目自定义差异” |
| 标准更新 | 规则元数据记录版本和复核日期 |
| 冲突处理 | 标准优先，项目规则可更严格但必须明确标注 |
| 许可边界 | 项目许可证不覆盖第三方标准文本 |
| 官方入口 | 优先链接到国家标准全文公开系统和行业标准官方页面 |
| 用户原文 | 默认只处理用户提供内容，不把用户文本并入公共规则库 |

## 11. 对后续开发的直接约束

1. 规则默认值必须按标准版本和配置文件解析。
2. `GB/T 7714-2015` 不能作为新文档默认。
3. 术语检查必须允许注入项目术语库。
4. 代码保护先于任何标点检测。
5. 每个诊断必须能追溯到内置规则或项目配置。
6. 每条规则必须有元数据、严重级别、可修复性、来源和测试。
7. 不把标准全文塞进仓库或测试快照。
8. 通用规则和场景规则分离。
9. 严格模式只提升已有警告，不暗中修改正文。
10. 标准更新时，先更新调研文档，再更新规则和测试。
